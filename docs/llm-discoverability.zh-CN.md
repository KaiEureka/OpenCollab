# 模型能力告知审计

[English](llm-discoverability.md)

这次审计沿着功能实现、角色配置、模型实际收到的提示与工具定义、调用执行、结果返回逐段检查。范围覆盖已经通过 PR 244 合入的运行能力，以及 PR 247 所在的虚拟机支持系列。

确认的问题分为八类，既包括已经实现的功能缺少发现入口，也包括提示要求模型使用当前配置中没有的操作。修复从实际配置生成模型需要的信息。

## 确认的问题与修复

| 编号 | 正常触发方式与影响 | 修复内容 | 执行依据 |
| --- | --- | --- | --- |
| D1 | Team 成员可以给自编 Workflow 填写隔离字符串，却没有收到已配置选项和编写接口说明，选择 VM 或自定义环境需要额外知识 | `manage_workflow` 展示实际注册的隔离名字与默认值，增加 `describe`，返回含义、继承工具权限、启动条件和可执行范例 | 公开 Team 调用可以发现 VM 选项且没有申请机器，另一个调用根据返回范例写入源码、启动真实 Python 子进程并收回两个 Agent 的结果 |
| D2 | `run_workflow` 只列出名字，输入提示笼统地说通常传 goal，Weave 实际需要任务组与验证命令，Reconstruct 需要任务集成 | 增加按名字读取输入说明的 `describe`，补齐三个内置 Workflow 的必需输入和用法 | 公开 Team 先读取自定义函数的输入说明再成功执行，三个内置 Workflow 都可在零模型调用下查询说明 |
| D3 | 开放拓扑遗漏已配置角色目录，受限角色可能被要求调用未授权的协调工具，预建 Team 又收到继续创建成员的提示 | 上下文列出可达角色及简短职责，只提及已配置的协调工具，并说明预建成员已经存在 | 检查开放拓扑、仅能投信的角色，以及公开 SDK 发出的预建 Team 模型请求 |
| D4 | 单 Agent 或 Workflow 可以直接使用技能工具，但缺少 Team 的上下文构造器时，模型拿不到技能名字与用途 | 技能工具自身的 schema 带上当前目录，空目录也明确说明 | 从 schema 发现技能并加载原文，另行检查目录更新和三种协议转换 |
| D5 | 禁止创建文件时，文件工具仍向模型展示 create 模式，子运行继承权限后也可能出现相同矛盾 | 工具导出的 schema 根据当前权限展示可执行模式，原写入检查继续生效 | 从展示的模式选择操作并完成真实文本替换，验证运行中收紧权限及实例相互独立 |
| D6 | Base 与 Single2 固定声称提供六个工具和 Shell，实际只读配置或自定义工具集合可能没有这些能力 | 根据实际工具定义使用操作，Shell 指令改为有条件使用，保留任务、安全和交付要求 | 捕获公开只读 Agent 的模型请求，确认工具和提示一致 |
| D7 | 无人工输入渠道的 Analyst 仍被要求先调用 ask_user，该工具实际已被移除 | 提示在工具可用时提问，对必需但尚未解决的决定说明缺项 | 检查默认无人工输入 Analyst 的工具集合与提示 |
| D8 | 串行 Team 的投信回执要求调用 submit，但发送者可能没有该工具，接收者又需要等待发送者结束当前轮次 | 明确可以用没有工具调用的最终回复结束轮次，submit 作为工具存在时的另一种方式 | 对没有 submit 的发送者执行投信，验证回执可以指导其让出执行机会 |

## 修复后的使用方式

成员编写 Workflow 前可以调用 `manage_workflow` 的 `describe`。返回信息包括实际注册的隔离选项、继承默认值、子 Agent 可用工具、可通过公开工具工厂构造的子集，以及函数入口和范例。模型可以把范例写成 Python 文件，再传入包含 tasks 的参数对象运行。

环境选项的状态明确写为分配时检查。已配置的 Docker 后端或虚拟机资源表示存在相应执行选项，连接、容量和实际分配由执行时的后端检查。发现操作不会启动容器或领取虚拟机。当前启动权限依据成员的 Bash 权限和执行环境计算。

调用已注册 Workflow 前，可以给 `run_workflow` 传入名字和 `describe` 动作，读取该函数的输入说明，再带 args 执行。自定义 Workflow 将调用者需要的输入说明放进函数 docstring，模块发现包装会保留这些信息。

## 程序配置边界

模型路由、请求并发额度、环境供应和运行默认值继续由程序员配置。这次修复补充现有 Agent 操作所需的发现信息。按角色限制隔离方式的授权策略，以及实时硬件目录，需要各自设计行为和接口。

环境申请继续经过已有检查，子工具继续继承父工具限制。查询说明保持模型调用、预算、硬件分配和候选状态不变。

## 验证方式

定向回归位于 [test_model_discoverability.py](../tests/interfaces/test_model_discoverability.py)。测试使用脚本化模型响应驱动真实 SDK、工具执行与受管理的 Python 子进程，并检查三种模型协议中的工具定义。

运行命令为 `uv run pytest -q tests/interfaces/test_model_discoverability.py`。修复 PR 会记录最终提交对应的完整测试、架构检查、依赖检查、安装包和 CI 结果。
