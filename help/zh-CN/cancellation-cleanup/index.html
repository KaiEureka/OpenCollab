预算、上下文与运行恢复

中断任务与检查资源清理

终端中用 Ctrl+C 中断当前轮次，Python 中取消运行任务，或给 SDK 调用设置 timeout，都能让执行进入停止与清理。随后应检查保存记录、最终用量和环境状态，再继续操作同一工作区。SDK 返回的 metrics 把会话结束与环境清理分别表示。

终端怎样中断

运行期间 Ctrl+C 会中断当前轮次并清空等待执行的输入，存在待回答问题时也会拒绝该问题。若会话已经空闲，Ctrl+C 退出。普通退出还可使用 /exit 或 /quit。停止后终端保留可用的部分回答，并显示停止或失败原因。

希望给某次运行固定期限时，SDK 的 timeout= 比外层定时取消更容易读取统一状态。运行期限到达时返回 status="stopped" 和 reason="timeout"。调用方主动取消则在框架拥有的清理阶段结束后传播 asyncio.CancelledError。

在 Python 中连接取消操作

下面展示一个由应用主动取消的完整任务。实际界面可以把 task.cancel() 接到停止按钮。示例只使用读取工具，模型设置沿用已准备的配置。

import asyncio
from opencollab import OpenCollab, RunControl

async def main() -> None:
    events = []
    client = OpenCollab(".")
    task = asyncio.create_task(client.agent(
        "阅读项目入口并整理主要模块。",
        tools="read",
        budget=100_000,
        cleanup_timeout=10,
        artifacts="artifacts/cancel-example",
        run_control=RunControl(on_event=events.append),
    ))
    await asyncio.sleep(1)
    if not task.done():
        task.cancel()
    try:
        result = await task
        print(result.status, result.reason)
    except asyncio.CancelledError:
        print("应用已收到取消结果")
    print([event.type for event in events])

asyncio.run(main())

cleanup_timeout 为有限正数，约束执行结束后的已拥有资源清理。单独的 RunControl.tool_cancellation_cleanup_timeout 可以调整工具取消清理等待。事件接收器需要同步返回，记录事件时宜快速保存，再由应用其它部分处理。

核对停止后的状态

session_quiesced 表示会话及持久化阶段已确认结束。框架创建并拥有执行环境时，还会报告 environment_quiesced，并汇总到 cleanup_quiesced 与 execution_quiesced。通过 result.metrics.get(...) 读取这些字段。

调用方传入的环境继续由调用方管理，SDK 的环境清理及汇总字段保持 None，直到调用方自己执行并确认相应清理。应用应依照自己创建环境的方式完成后续处理。会话已经停止和工作区适合下次写入，需要分别检查。

Workflow 的 ctx.agent_run 返回受控调用结果，其中 workspace_ready 直接用于决定共享上下文是否可以开始后续工作。超时后仍有 provider 或工具工作在清理时，调用会等待自己的资源，清理未完成时返回失败并阻止共享上下文继续执行。工作流继续拥有待结束任务及其保留预算。

保存用量与部分改动

取消发生时已经显示的 token 统计可能还会变化。迟到的 provider 成功或错误用量在框架拥有的清理阶段结算一次，usage 事件的 late 与 purpose 可帮助识别来源，cleanup_completed 标记该接收器所属运行的清理结束。最终花费结合持久化用量记录判断。

失败或停止的 Team 子成员仍可交回已有改动。补丁捕获失败，或返回消息容纳不下完整补丁时，原生工作树会保留完整文件并报告恢复位置。先导出所需改动，再按工作区恢复指南释放工作树。开始下一次任务前，确认会话清理结果以及自己负责的环境状态，随后检查工作区差异。
